## 一、渲染技术对比

### 1.1 Canvas vs SVG vs WebGL
           
| 维度 | SVG | Canvas 2D | WebGL |
| --- | --- | --- | --- |
| **适用场景** | 编辑器（节点数 <1000） | 数据可视化、图表 | 游戏、3D、大型可视化 |
| **DOM 事件** | 原生支持 | 需手动绑定 | 需射线投射 |
| **内存占用** | 高（每个元素是 DOM） | 低（位图） | 中等 |
| **重绘粒度** | 元素级 | 全量/区域 | 全量/区域 |
| **缩放质量** | 矢量无损 | 位图有锯齿 | 可过滤优化 |
| **实现复杂度** | 低 | 中 | 高 |
| **Node-RED 选用** | ✅ SVG | ❌ | ❌ |

### 1.2 工业级画布库对比
          
| 库 | 渲染 | 虚拟化 | 缩放范围 | 移动端 |
| --- | --- | --- | --- | --- |
| Konva | Canvas | ✅ | 自定义 | ✅ |
| Fabric.js | Canvas | ✅ | 自定义 | ✅ |
| D3.js | SVG | ❌ | 依赖实现 | ✅ |
| Leaflet | Canvas/Image | ✅ | 有限 | ✅ |
| PixiJS | WebGL | ✅ | 任意 | ✅ |
| Excalidraw | Canvas | ❌ | 0.1x-10x | ✅ |

## 二、Node-RED 画布实现分析

### 2.1 固定空间画布
Node-RED 使用**固定 8000×8000 SVG 空间**，通过 CSS scroll 模拟平移。

```text
outer = d3.select("#red-ui-workspace-chart")
    .append("svg:svg")
    .attr("width", 8000)    // 固定画布尺寸
    .attr("height", 8000)
    .style("overflow", "scroll");  // CSS 滚动
```

**优点:**实现简单，浏览器原生滚动 | **缺点:**大画布下 DOM 节点多，内存压力大

### 2.2 dirty flag 优化
Node-RED 不计算 viewport 裁剪，而是用 **dirty flag** 避免不必要重绘。

```text
// 节点/连线变更时标记 dirty
node.dirty = true;
node.dirtyGroup = true;

// redraw() 只重绘脏区域
if (node.dirty) {
    // 重绘该节点
}
```

## 三、性能优化技术

### 3.1 视口裁剪（Viewport Culling）原理
**核心思想:**只渲染视口内可见的元素。

```javascript
function getVisibleNodes(viewport, nodes) {
    const { x, y, width, height, scale } = viewport;
    const viewBounds = {
        left: x / scale, right: (x + width) / scale,
        top: y / scale, bottom: (y + height) / scale
    };
    return nodes.filter(node => rectsIntersect(viewBounds, getNodeBounds(node)));
}

function rectsIntersect(a, b) {
    return !(a.right < b.left || a.left > b.right ||
             a.bottom < b.top || a.top > b.bottom);
}
```

**性能收益:**10000 节点场景下，视野内通常 <100 节点，DOM 操作减少 99%。

### 3.2 矩阵变换（缩放/平移数学）

```text
// 齐次坐标变换
[x'] = [scale  0    tx] [x]
[y'] = [0      scale ty] [y]
[1 ] = [0      0     1 ] [1]

// 以屏幕中心点为缩放中心
function zoomAtPoint(viewport, newScale, centerScreen) {
    const centerBefore = screenToCanvas(viewport, centerScreen);
    viewport.scale = newScale;
    const centerAfter = screenToCanvas(viewport, centerScreen);
    viewport.x += (centerAfter.x - centerBefore.x) * viewport.scale;
    viewport.y += (centerAfter.y - centerBefore.y) * viewport.scale;
}
```

### 3.3 LOD (Level of Detail) 策略
       
| 缩放级别 | 渲染内容 |
| --- | --- |
| > 50% | 完整节点 + 标签 |
| 20%-50% | 简化节点（无标签） |
| < 20% | 占位符方块 |

### 3.4 requestAnimationFrame 优化

```javascript
let rafId = null;
let pendingUpdate = false;

function scheduleRedraw() {
    if (!pendingUpdate) {
        pendingUpdate = true;
        rafId = requestAnimationFrame(() => {
            pendingUpdate = false;
            render(viewport);
        });
    }
}
```

### 3.5 Web Workers 在画布渲染中的应用
**适合放入 Worker 的任务:**

 
- 视口裁剪计算 
- 连线路径计算（Bezier 曲线） 
- 布局算法（dagre, elkjs） 
- 搜索/过滤

## 五、实现方案推荐

### 5.1 编辑态（节点编辑器）
**推荐: Canvas 2D (Konva.js)** — 性能好，支持绑定，API 友好

### 5.2 运行态（监控/预览）
推荐: 虚拟化 Canvas — 只渲染视口内元素，Web Worker 处理裁剪计算。

### 5.3 混合方案
        
| 场景 | 技术 |
| --- | --- |
| 节点编辑 | Konva (Canvas) |
| 流程监控 | Canvas 虚拟化 |
| 子流程预览 | WebGL (PixiJS) |
| 缩略图/小地图 | Canvas 降采样 |

## 六、CogniFlow 画布实现建议
基于 Node-RED 和业界实践，推荐：

 
- **初期:** SVG + D3（类似 Node-RED），快速开发 
- **中期:** 引入 dirty flag + viewport culling 
- **后期:** Canvas (Konva) 迁移，支持大规模流程 
**关键优化点:**

 
- 用 requestAnimationFrame 节流重绘 
- Web Worker 处理布局计算 
- 缩放时用 LOD 降级渲染细节 
- 连线路径用 Path2D 缓存
