# 规则引擎画布编辑器开发计划
Phase 0-6 完整规划、系统架构、节点类型体系、执行引擎架构

---

## 一、项目背景
CogniFlow 规则引擎是一个**可视化编排**的视觉感知处理引擎，允许用户通过节点编辑器定义"检测→处理→动作"的完整流程。参考对象是 ComfyUI（最成熟的 AI 节点编辑器）和 Node-RED（工业级流程编排工具）。

### 1.1 核心功能目标
         
| 目标 | 描述 |
| --- | --- |
| **可视化编排** | 无限画布上通过拖拽、连接节点来构建规则流程 |
| **节点类型化** | 输入、检测、处理、动作、逻辑、输出六类节点，类型安全连接 |
| **智能执行** | Kahn 拓扑排序 + 层内并行，支持条件分支 |
| **实时反馈** | WebSocket 推送执行进度，支持中断 |
| **持久化** | 规则图保存/加载，支持版本管理 |

### 1.2 现状评估
         
| 维度 | 现状 | 差距 |
| --- | --- | --- |
| 前端画布 | RuleCanvas.vue 基础布局已完成 | 缺少节点拖拽、类型检查、撤销重做 |
| 后端 API | CRUD + 执行接口已有 | 执行引擎是串行，缺拓扑排序和并行 |
| 节点定义 | 无统一类型系统 | 需要新建节点注册表 |
| 实时通信 | WebSocket 基础已有 | 缺执行进度推送 |
| 变量系统 | 有 variables_json 字段 | 缺表达式解析和绑定 UI |

## 四、阶段验收标准

### Phase 1：节点类型系统（后端）

 
- GET /api/rule-engine/nodes/definitions 返回完整的 6 类节点定义 
- 节点面板能够按类别分组展示（前端可验证） 
- 每个节点执行器能独立执行并返回输出（单元测试覆盖） 
- 新增节点只需注册到 NodeRegistry，无需修改其他代码 

### Phase 2：执行引擎核心（后端）

 
- 规则图执行顺序与拓扑依赖关系一致 
- 无环图正常执行，有环图报错并返回环节点信息 
- 单层内多节点并行执行，总耗时 ≈ 最慢节点耗时 
- 执行中途可取消，已执行的节点结果不丢失 

### Phase 3：画布交互基础（前端）

 
- 从左侧面板拖拽节点到画布，节点正确创建 
- 两节点间连线，类型匹配时允许，类型不匹配时拒绝并提示 
- 选中节点按 Delete 可删除 
- Ctrl+Z/Y 可撤销/重做（至少 20 步） 

### Phase 4：节点配置面板（前端）

 
- 选中节点后，右侧面板正确显示节点类型、ID、名称 
- 输入参数表单根据节点类型动态生成 
- 变量下拉菜单能插入 {{variable_name}} 到输入框 

### Phase 5：实时通信（前后端）

 
- 执行规则时，前端收到 node_started → node_executed 逐节点推送 
- 进度条实时更新（当前层级 / 总层级） 
- 连接断开时自动重连 

### Phase 6：规则激活与触发

 
- 手动触发：点击按钮立即执行规则 
- 定时触发：可配置 Cron 表达式，按计划执行 
- Webhook 触发：提供 Webhook URL，外部请求触发执行 

## 五、风险识别与应对
         
| 风险 | 可能性 | 影响 | 应对措施 |
| --- | --- | --- | --- |
| Vue Flow 功能限制，无法满足复杂交互 | 中 | 高 | 考虑混用 Canvas 自绘节点（参考 ComfyUI） |
| 节点并行执行导致竞态条件 | 中 | 高 | 使用 asyncio.Lock 保护共享资源 |
| 大规模节点（100+）性能下降 | 中 | 中 | 虚拟化渲染 + Web Worker |
| WebSocket 断连重连 | 高 | 低 | 自动重连 + 消息缓冲 |
| 定时任务与服务器重启 | 低 | 中 | APScheduler + 数据库持久化 |

## 六、后续扩展方向

 
- **自定义节点：**用户可编写 Python 代码创建自定义节点 
- **子图嵌套：**支持节点引用另一个规则图，实现子流程复用 
- **版本管理：**规则图版本历史、回滚 
- **协作编辑：**多用户同时编辑同一规则图（CRDT） 
- **模型市场：**用户可上传/下载预训练的规则图模板
