视频流推理设计方案

实时帧流推理架构、WebSocket 推送、Canvas 渲染

一、背景与目标

1.1 问题描述

当前 CogniFlow 的视频检测方案采用异步批量处理模式：

  • 用户上传视频 → 等待全部处理完成 → 下载结果视频
  • 问题：无法实时预览检测效果，用户体验不连续

1.2 目标

实现实时帧流推理：

  • 边推理边在 Web 前端预览检测效果
  • 支持 24fps 实时推理与渲染
  • 保持与现有图片检测一致的用户体验

2.2 核心设计

2.2.1 推理-推送解耦（生产者-消费者模式）

推理线程（Producer）：
  - 不断从视频取帧
  - 批量推理（如每 8 帧为一批）
  - 结果放入帧队列

推送线程（Consumer）：
  - 从帧队列取数据
  - 通过 WebSocket 发送给前端
  - 控制推送节奏（24fps）

2.2.2 批量推理优化

当前（逐帧推理）：
  每帧：读取 → GPU传输 → 推理 → CPU回传 → 绘制 → 写入
  耗时：约 17-25ms/帧

优化后（批量推理，batch_size=8）：
  每批：批量 GPU传输 → 批量推理 → 批量回传
  耗时：约 3-5ms/帧（提升 5-8 倍）

2.2.3 推送频率控制

问题：推理速度可能快于/慢于 24fps

解决：
- 推理快：丢弃中间帧，保持 24fps 推送
- 推理慢：降帧处理，通知前端当前实际帧率

三、接口设计

3.1 发起推理请求

POST /inference/detect/video/stream
Content-Type: multipart/form-data

参数：
  - file: 视频文件
  - model_id: 模型 ID
  - conf_threshold: 置信度阈值（默认 0.25）

响应：
{
  "success": true,
  "job_id": "abc123",
  "stream_url": "ws://host/api/ws/inference/stream/abc123",
  "video_info": {
    "fps": 24,
    "total_frames": 1440,
    "duration": 60.0
  }
}

3.2 WebSocket 连接

WS /ws/inference/stream/{job_id}

消息类型：
  - frame: 单帧推理结果
  - complete: 推理完成
  - error: 错误信息

3.3 停止推理

POST /inference/stop/{job_id}

响应：
{
  "success": true,
  "message": "推理已停止"
}

五、前端渲染方案

5.1 Canvas 渲染流程

  1. WebSocket 接收 base64 帧数据
  2. Image 对象加载
  3. drawImage 绘制原帧
  4. 遍历 detections，绘制检测框 + 标签
  5. requestAnimationFrame 控制渲染节奏

5.2 播放控制

  • 播放/暂停：控制 requestAnimationFrame 的执行
  • 进度条：显示已处理帧数 / 总帧数
  • 倍速：调整帧间隔（如 0.5x = 每帧停留 2 个渲染周期）

六、兼容性设计

6.1 双模式并存

现有模式（异步批量处理）：保留，用户可选择；新增模式（实时流推理）：通过 Tab 切换。

6.2 降级处理

如果 WebSocket 连接失败：自动降级到轮询模式（复用现有 /video/status/{job_id}）。
