规则引擎节点系统参考手册

节点角色分析 · 端口类型系统 · 连接矩阵 · 推理链组合模式

一、推理链全景图

一条完整的推理链遵循以下流动方向：

触发层 → 输入层 → 检测层 → 处理层 → 逻辑/条件层 → 动作层 → 输出层

节点之间通过 端口类型系统 约束连接规则，共有 14 种端口类型（IMAGE、BBOX、MASK、SCORES、TRIGGER、CONTROL、MODEL、INT、FLOAT、BOOLEAN、STRING、ARRAY、OBJECT、ANY）。

二、节点分类总览

系统共实现 26 个节点类型，划分为 6 个功能分类：

分类 节点数 功能 颜色
input 8 触发 + 数据采集（触发器 5 + 采集 3） 绿色
detection 3 目标检测模型推理 青色
processing 4 数据变换与增强 黄色
action 5 外部操作执行（键盘/鼠标/HTTP 等） 橙色
logic 8 流程控制 + 条件分支 紫色
output 3 结果输出/持久化 红色

三、各节点角色与连接规则

3.1 触发层（Trigger Layer）— 5 个节点

所有触发节点没有输入端口，只能作为 DAG 的源节点。输出类型兼容 TRIGGER 和 CONTROL 端口。

manual_trigger manual

手动触发 — 无配置参数
输入端口
（无）
输出端口
BOOLEAN triggered
后续可连：动作节点（需 CONTROL/TRIGGER 端口）、逻辑节点

timer_trigger timer

定时触发 — interval(0.1-3600s, 默认5s), enabled
输入端口
（无）
输出端口
BOOLEAN triggered
FLOAT timestamp

cron_trigger cron

Cron 调度 — 5 字段 cron 表达式，时区选择
输入端口
（无）
输出端口
BOOLEAN triggered
FLOAT timestamp

webhook_trigger webhook

外部 HTTP 触发 — path、method(GET/POST/PUT/DELETE)
输入端口
（无）
输出端口
BOOLEAN triggered
ANY request_data
注意：request_data: ANY 可连 ANY 端口，这是外部数据进入规则图的入口之一。

api_trigger api

内部 API 触发 — api_name
输入端口
（无）
输出端口
BOOLEAN triggered
ANY api_response

3.2 输入层（Input Layer）— 3 个节点

输入节点也是 DAG 源节点（无输入端口）。image: IMAGE 输出只能连接 IMAGE 或 ANY 类型输入端口。

image_capture capture

从文件路径或 URL 加载图像 — source(文本)
输入端口
（无）
输出端口
IMAGE image
INT width
INT height
后续可连：检测节点（需 IMAGE）、预处理节点、ANY 端口
待完善：source 字段目前是文本输入，未集成文件选择器或 URL 校验。

video_capture video

从视频流捕获帧 — source(默认"video0")、fps(1-120)
输入端口
（无）
输出端口
IMAGE image
INT frame_id
FLOAT timestamp
注意：持续输出帧流，适合实时检测场景。后续同 image_capture。

screen_capture screen

屏幕截图 — source(screen/window)
输入端口
（无）
输出端口
IMAGE image
OBJECT region(可选)
待完善：region 输出的序列化方式未在端口类型系统中明确定义。

3.3 检测层（Detection Layer）— 3 个节点

检测节点需要 IMAGE 输入，产出结构化检测数据。视觉专用类型（BBOX/SCORES）仅与自身或 ANY 兼容。

yolo_model YOLO

YOLO 目标检测 — model_id(需选择)、confidence(0-1)、iou_threshold、max_detections、device
输入端口
IMAGE image (必需)
输出端口
BBOX bboxes
SCORES scores
ARRAY class_ids
ARRAY class_names
INT count
后续可连：条件节点(ARRAY→detections)、处理节点(ARRAY→detections 或 BBOX→filter)、变量节点(INT→counter)
待完善：configSchema 中有 model-select widget 类型，但未实现从后端动态获取模型列表的接口联动。

yolo_trigger yolo-trigger

YOLO 触发兼检测（双角色）— model_id、class_names、min_confidence
输入端口
IMAGE image (可选)
输出端口
BOOLEAN triggered
ARRAY detections
特殊角色：兼做触发 + 检测。无 IMAGE 输入时也可做纯 trigger 使用。

object_detector detector

通用目标检测 — model_type(yolo/ssd/mtcnn)、confidence
输入端口
IMAGE image (必需)
输出端口
ARRAY detections
INT count

3.4 处理层（Processing Layer）— 4 个节点

处理节点输入端口类型精确（ARRAY/IMAGE），需要上游提供匹配类型的数据。

filter filter

过滤检测结果 — filter_by(class/confidence/count)、min_confidence、min/max_count
输入端口
ARRAY detections (必需)
输出端口
ARRAY filtered
INT count
后续可连：条件节点、输出节点、tracker 节点

tracker tracker

目标跟踪 — tracker_type(sort/deepsort/bytetrack)、max_age
输入端口
ARRAY detections (必需)
输出端口
ARRAY tracked
ARRAY track_ids

category_encode encode

类别编码映射 — class_mapping("name:id,..." 格式)
输入端口
ARRAY class_names (必需)
输出端口
ARRAY class_ids
ARRAY class_names
典型连接：yolo_model.class_names → category_encode.class_names

image_preprocessor preprocess

图像预处理 — operation(resize/crop/normalize/augment)、width、height
输入端口
IMAGE image (必需)
输出端口
IMAGE image
典型用途：在检测节点之前串联做预处理。多个检测节点可共享同一个预处理输出。

3.5 逻辑 / 条件层 — 8 个节点

分支控制（3 个）

branch branch

条件分支 — 无配置参数
输入端口
BOOLEAN condition (必需)
输出端口
CONTROL true
CONTROL false
典型连接：condition 端口连接条件节点的 result 输出。true/false 分别连动作节点。

parallel_branch parallel

三路并行分发 — max_concurrent
输入端口
TRIGGER trigger
输出端口
CONTROL branch_1
CONTROL branch_2
CONTROL branch_3

delay delay

延时控制 — delay(0.1-60s, 默认1.0)
输入端口
CONTROL input
输出端口
CONTROL output
典型连接：串联在动作序列中间做延时。

变量操作（2 个）

set_variable set-var

设置变量 — variable_name、value、value_type(static/dynamic)
输入端口
TRIGGER trigger (可选)
输出端口
CONTROL next
变量引用：该节点设置的变量可通过 {{variable_name}} 在其他节点的配置字段中引用。

counter counter

计数器 — variable_name、increment、reset_on_trigger、max_value
输入端口
TRIGGER trigger
输出端口
INT count
BOOLEAN overflow

条件判定（3 个）

object_exists_condition exists

目标存在判定 — class_names、min_count、comparison(gte/lte/eq/gt/lt)
输入端口
ARRAY detections (必需)
输出端口
BOOLEAN result
INT matched_count
典型连接：result → branch.condition，实现"检测到目标时执行动作"。

confidence_threshold_condition confidence

置信度阈值判定 — min_confidence(0-1, 默认0.5)
输入端口
ARRAY detections (必需)
输出端口
BOOLEAN result
FLOAT max_confidence

variable_condition var-cond

变量值比较 — variable_name、expected_value、comparison(eq/ne/gt/lt/gte/lte/contains)
输入端口
（无）
输出端口
BOOLEAN result
ANY actual_value
注意：直接读取变量，无需上游连接。通过 {{variable_name}} 引用变量。

3.6 动作层（Action Layer）— 5 个节点

所有动作节点需要 TRIGGER 类型输入（来自触发节点或 logic 节点的 CONTROL 输出）。输出可回连到 branch 做重试/容错。

keyboard_action keyboard

键盘操作 — keys(多选)、hold_duration、interval
输入端口
TRIGGER trigger
输出端口
BOOLEAN success
ARRAY executed_keys

mouse_action mouse

鼠标操作 — action(click/move/scroll/double_click/right_click)、x、y、button
输入端口
TRIGGER trigger
输出端口
BOOLEAN success

wait_action wait

等待/延时 — duration(slider, 0.1-300s, 默认1.0)
输入端口
TRIGGER trigger
输出端口
BOOLEAN completed
典型用途：在动作序列中间插入等待。

http_request_action HTTP

HTTP 请求 — url、method、headers(JSON)、body(JSON)、timeout
输入端口
TRIGGER trigger
输出端口
BOOLEAN success
INT status_code
ANY response
典型用途：调用外部 API，response 数据可用于后续节点（如 set_variable）。

log_action log

日志记录 — message(textarea)、level(debug/info/warning/error)
输入端口
TRIGGER trigger
输出端口
BOOLEAN logged
典型用途：调试/记录，一般是推理链的终点。

四、端口类型兼容矩阵

以下矩阵定义了哪种源端口类型可以连接到哪种目标端口类型。类型兼容性是前后端双重校验的——画布上连接时前端校验，执行时后端再次校验。

源类型 兼容目标类型
ANY全部 14 种类型（万能桥接）
IMAGEANY, IMAGE
BBOXANY, BBOX
MASKANY, MASK
SCORESANY, SCORES
TRIGGERANY, TRIGGER, CONTROL
CONTROLANY, CONTROL
MODELANY, MODEL
INTANY, INT
FLOATANY, FLOAT
BOOLEANANY, BOOLEAN
STRINGANY, STRING
ARRAYANY, ARRAY
OBJECTANY, OBJECT
关键规则：
  • 端口类型仅决定是否允许连接，不保证运行时数据格式正确
  • TRIGGER 输出可连 CONTROL 输入，反之不成立（单向兼容）
  • CONTROL 仅用于逻辑/动作链串联，不传递业务数据
  • ANY 类型是万能桥接，但宽松的连接可能导致运行时类型错误

五、典型推理链组合模式

模式 1：定时屏幕检测

cron_trigger → screen_capture → yolo_model → filter → object_exists_condition → branch
├─ true → mouse_action → log_action
└─ false → wait_action

模式 2：Webhook 触发检测 + 保存

webhook_trigger → image_capture → image_preprocessor → yolo_model → save_result → notification

模式 3：视频流实时检测 + 追踪

video_capture → yolo_model → tracker → filter → object_exists_condition → branch
├─ true → keyboard_action → http_request_action
└─ false → counter

模式 4：多相机并行检测

parallel_branch → image_capture → yolo_model
screen_capture → object_detector
→ save_result

模式 5：带计数和变量的条件检测

timer_trigger → image_capture → yolo_model → confidence_threshold_condition → branch
├─ true → counter → variable_condition → branch → http_request_action
└─ false → delay
