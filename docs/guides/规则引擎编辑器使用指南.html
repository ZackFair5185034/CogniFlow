1.2 创建和打开规则

  • 创建新规则：在规则列表页点击「新建规则」，填写名称和描述后进入编辑器。
  • 打开已有规则：在规则列表页点击规则卡片，进入编辑器继续编辑。
  • 重命名：在编辑器顶部直接点击规则名称输入框修改，失去焦点后自动保存。
  • 状态查看：顶部显示规则当前运行状态（运行中/已停止）。

1.3 添加节点

  • 从面板拖拽：左侧节点面板按类别折叠组织，点击展开类别，拖拽节点到画布任意位置。
  • 搜索节点：面板顶部搜索框输入关键词，实时过滤匹配的节点类型。
  • 自定义标签：添加后可在节点标题栏修改显示标签，便于区分多个同类型节点。

1.4 配置节点参数

每个节点都有自己的配置面板，直接在节点上操作。系统会根据参数类型自动渲染对应的控件：

变量绑定

每个配置项右侧都有一个 📎 按钮，点击可弹出变量列表，选择变量后自动插入 {{变量名}} 引用。运行时会用实际值替换变量引用。

1.5 连接节点

  • 建立连接：从节点右侧输出端口（圆点）拖出连线到另一节点左侧输入端口。
  • 端口匹配：端口会校验类型兼容性，不兼容的端口无法连接。
  • 删除连线：点击选中连线（高亮），按 Delete 键删除，或右键选择删除。
  • 连接规则：输出→输入单向连接，不能形成环形依赖（执行引擎按拓扑排序）。
  • 多输出：一个输出端口可连接多个下游节点（数据分发）。
  • 多输入：一个输入端口只能接收一个上游连接（数据合并需使用逻辑节点）。

1.7 右键上下文菜单

  • 复制：复制选中的节点到剪贴板
  • 粘贴：将复制的节点粘贴到鼠标位置
  • 剪切：剪切选中节点
  • 删除：删除选中的节点或连线
  • 复制（含配置）：完全复制节点，保留所有参数配置

1.8 变量管理

右侧变量面板用于管理可在规则中引用的全局变量：

  • 添加变量：点击「+ 添加变量」按钮
  • 变量字段：变量名（字母数字下划线）+ 类型（STRING / NUMBER / BOOLEAN / IMAGE / BBOX）
  • 类型颜色：STRING=青色, NUMBER=黄色, BOOLEAN=紫色, IMAGE=绿色, BBOX=蓝色
  • 变量引用：在节点配置中使用 {{变量名}} 语法引用
  • 删除变量：点击变量行末尾的删除按钮

1.9 执行与调试

  • 手动执行：点击工具栏「执行」按钮，立即触发一次规则执行。
  • 执行日志：底部面板实时显示每个节点的执行状态（idle→running→success/failed）。
  • WebSocket 状态：顶部工具栏显示 WebSocket 连接状态（已连接/未连接），未连接时执行结果无法实时推送。
  • 结果查看：执行完成后，底部面板显示每个节点的输出数据。
  • 保存并激活：规则配置完成后，可在规则列表页激活规则，使其按触发器配置自动执行。

三、配置测试用例

以下是从简单到复杂的完整配置示例。每个用例包含连接图、节点参数配置、预期效果。

用例 1：基础检测流水线

目标：采集一张图片 → YOLO 检测 → 保存检测结果。

[ImageCapture] ──image──→ [YOLOModel] ──detections──→ [SaveResult]
1 添加 ImageCaptureNode

参数：device_id=0, interval=1.0 — 使用默认摄像头

2 添加 YOLOModelNode

参数：model_id=(选择已训练的模型), confidence=0.5, iou_threshold=0.45, device=auto

从 ImageCapture.image → 连接到 YOLOModel.image

3 添加 SaveResultNode

参数：format=json, save_path=(留空自动生成)

从 YOLOModel（任意输出）→ 连接到 SaveResult.data

预期效果：
点击执行 → ImageCapture: 采集成功, 输出 {path: "...jpg"}
YOLOModel: 检测到 N 个目标, 输出 {bboxes, scores, class_names, count}
SaveResult: 检测结果保存为 JSON 文件
count > 0 表示检测到目标

用例 2：预处理增强流水线

目标：截图 → 缩放到统一尺寸 → YOLO 检测 → 输出日志。
适用于分辨率不统一的输入源。

[ScreenCapture] ──image──→ [ImagePreprocessor] ──image──→ [YOLOModel] ──count──→ [LogAction]
1 添加 ScreenCaptureNode

参数：region=fullscreen, fps=1 — 截取全屏

2 添加 ImagePreprocessorNode

参数：operation=resize, width=640, height=640

从 ScreenCapture.image → 连接到 ImagePreprocessor.image

3 添加 YOLOModelNode

参数：model_id=(选择模型), confidence=0.5, max_detections=100

从 ImagePreprocessor.image → 连接到 YOLOModel.image

4 添加 LogActionNode

参数：level=info, message="检测到 {{count}} 个目标"

从 YOLOModel.count → 连接到 LogAction.message（使用变量绑定绑定 count 输出）

预期效果：
ImagePreprocessor: 将截图 resize 到 640x640
YOLOModel: 检测到目标
LogAction: 输出日志 "检测到 3 个目标"
关键：ImagePreprocessor 将不同分辨率的截图统一为 640x640，提高检测稳定性

用例 3：条件触发检测

目标：检测到 person 时触发鼠标点击操作，否则记录日志。

[ManualTrigger] ──→ [ObjectExists] ──true──→ [MouseAction]
[ManualTrigger]──→ [ObjectExists] ──false──→ [LogAction]
1 添加 ImageCapture + YOLOModel + Filter

ImageCapture: device_id=0
YOLOModel: model_id=(选择模型), confidence=0.5
Filter: min_confidence=0.6 — 只保留高置信度

ImageCapture → YOLOModel → Filter (串联)

2 添加 ObjectExistsConditionNode

参数：target_class="person", min_count=1

从 Filter.filtered → 连接到 ObjectExists.detections

3 添加 ManualTrigger 驱动执行

ObjectExists 需要布尔输入，ManualTrigger 触发信号可作为条件来源。

ManualTrigger.triggered → ObjectExists.condition（通过 BranchNode 或直接连接）

4 添加 MouseAction + LogAction

MouseAction: action=click, button=left, x=500, y=400
LogAction: level=info, message="未检测到目标"

从 YOLOModel.scores → 连接到 ConfidenceThreshold.scores
从 YOLOModel.count → 连接到 ObjectExists.detections（将 count 作为检测数量输入）

BranchNode B: ObjectExists.result → BranchB.condition

从 BranchB.true → 连接到动作节点的 trigger 端口。

四、最佳实践与常见问题

4.1 性能优化建议

  • 减少采集频率：Camera/VideoCapture 的 fps 和 interval 不要设置过低，建议 fps ≤ 10，interval ≥ 0.5s，避免 CPU/GPU 过载。
  • 适当地使用 Filter：在 YOLO 检测后接 Filter 节点过滤低置信度结果，减少下游处理压力。
  • 利用并行分支：无依赖关系的下游节点会并行执行。将耗时操作（如 HttpRequest、SaveResult）与轻量操作（如 LogAction）并列放置。
  • 谨慎使用高帧率跟踪：TrackerNode 的 min_hits 设置过低（如 1）可能导致大量误检轨迹，建议 min_hits ≥ 3。
  • SQLite 写操作频率：SaveResultNode 频繁写入（每秒多次）可能成为瓶颈，建议通过 CounterNode 或 TimerTrigger 控制写入频率。

4.2 常见配置错误

错误现象原因解决方案
点击执行无任何输出 节点未正确连线，或触发器未连接 检查规则图是否有至少一个输入节点（ManualTrigger/TimerTrigger 等），并确认连线完整
YOLO 检测结果为空 置信度阈值过高，或模型未选择 降低 confidence 到 0.25-0.3 测试，确认 model_id 已选择模型
端口无法连接 端口类型不兼容 确认输出端口类型与输入端口类型匹配（如 SCORES 不能连接到 IMAGE 端口）
变量绑定不生效 变量名拼写错误或变量不存在 使用变量面板的「📎」按钮选择变量，避免手工输入拼写错误
规则保存失败 存在孤立节点或未完成的连线 使用「校验」功能检查规则图，修复所有校验错误后保存
WebSocket 连接断开 网络问题或后端服务重启 刷新页面重新连接，检查后端服务状态

4.4 调试技巧

  • 逐步验证：在构建复杂规则时，先搭建简单链路（如 Input→Output）确认基础连通性，再逐步添加中间节点。
  • 使用 LogAction 调试：在关键节点后添加 LogAction 节点输出中间数据，帮助定位问题。
  • 观察底部日志面板：执行日志面板显示每个节点的执行状态和耗时，红色节点表示执行失败。
  • 使用 ManualTrigger 测试：在配置 Cron/Timer 触发规则前，先用 ManualTrigger 手动测试逻辑正确性。
  • WebSocket 状态监控：工具栏的 WS 状态指示灯显示实时连接状态，确保执行结果能推送回前端。
  • 增量保存：每配置好一个节点或连线后就保存，避免意外丢失配置。
