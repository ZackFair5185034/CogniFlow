### 10.2 执行超时保护 ✅ 已完成
**问题：** 当前节点执行没有超时机制。如果某个节点（如 http_request_action 请求外部服务、yolo_model 加载大模型）卡住，整个执行引擎会无限等待。

**解决方案：**
- 全局默认超时：300s（5 分钟），可在执行上下文中覆盖
- BaseExecutor 可选 `default_timeout` 类属性，子类（如 yolo_model）可覆盖
- 专用 `node_timeout` WebSocket 事件（区别于通用 `node_failed`，前端用 warning 级别展示）
- 超时后标记节点为 `timeout`，继续执行下游（断路器模式）
- 12 个单元测试覆盖默认/上下文/显式/子类/事件/端到端六类场景

**涉及文件：**
- `backend/services/rule_engine/executor.py` — `_execute_node()` 使用 `asyncio.wait_for()`
- `backend/services/rule_engine/nodes/base.py` — BaseExecutor `default_timeout` 字段
- `backend/websocket_manager.py` — `send_node_timeout()` 新增
- `webui/src/views/RuleCanvas.vue` — `case 'node_timeout'` 处理
- `backend/tests/test_rule_engine/test_execution_timeout.py` — 12 个测试

✅ **验收通过**：模拟 sleep 超过 default_timeout 的节点，确认执行引擎在超时后继续执行下游节点；前端 warning 级别提示。

## Phase 14: 真实生产 Bug 修复 ✅ 已完成

### 14.1 graph_manager 不识别 VueFlow 节点 type="ruleNode" ✅ 已完成
**问题**：Phase 13.4 验收修复只把 `{"custom","group","default","input","output"}` 加入 VueFlow 占位 type 白名单，但前端 VueFlow 实际节点 type 是 `"ruleNode"`（小写驼峰），不在白名单内。`get_node_type()` 在第 197 行 `if top and top not in _VUEFLOW_PLACEHOLDER_TYPES: return top` 直接返回 `"ruleNode"`，**根本不会落到 `data.type` 兜底**。

**表现**：前端 VueFlow 保存的所有图 100% 报"没有起始触发器节点"或"存在孤立节点"，**完全无法保存**。Phase 13.4 "E2E 验收" 用的 `manual_trigger → merge_detections` 路径不经过 trigger 节点检查分支，所以漏掉了这个 bug。

**修复**：改用更鲁棒的规则——`data.type` 永远是权威业务类型（前端 VueFlow 总是设置，后端直存也常设置），顶层 type 仅作 `data.type` 缺失时的兜底。

**回归覆盖**（5 测试）：
- VueFlow 格式 manual_trigger 通过
- VueFlow 格式 yolo_trigger 单节点通过（不视为孤立）
- VueFlow 格式 manual → yolo_trigger 连边通过
- 后端直存格式（顶层 type）仍通过（向后兼容）
- VueFlow 格式无连接 action 节点仍报孤立（防止过度放宽）

**涉及文件**：`backend/services/rule_engine/graph_manager.py` + `test_graph_validate_vueflow.py`

## Phase 15: 画布性能优化 ✅ 已完成

**驱动**：根据 `docs/research-md/规则引擎画布性能分析.md` 的根因诊断（拖拽每帧 O(N) 重渲染 + JSON 深克隆 + Vue3 深代理）实施的 6 项核心优化 + 2 项体验优化。

### 15.1 shallowRef 替换 ref（Stage 1.1）

**问题**：`nodes`/`edges` 用 `ref()` 触发 Vue3 深代理，节点数据是 VueFlow 内部异构树（position/dimensions/internals 等），深代理无意义且拖累 200+ 属性追踪。

**修复**：`ruleEngine.ts:80-88` 改 `shallowRef`。仅追踪顶层数组引用变更。

### 15.2 VueFlow manual control（Stage 1.2）

**问题**：`v-model:nodes` 让 VueFlow 每帧（60Hz）回写 `nodes.value` 整图数组 → 触发所有 watcher 重算 → 30 节点图每秒 1800 次 computed。

**修复**：
- `:nodes` 单绑 + `@nodes-change` 事件
- 用 `useVueFlow()` 暴露的 `applyNodeChanges` / `applyEdgeChanges` 实例方法
- 拖拽中（`dragging=true`）的 position 变化被 `handleNodesChange` 过滤掉
- 仅拖拽结束（`dragging=false`）或非 position 类型变更才写回 store
- 同理 `handleEdgesChange`

**涉及文件**：`webui/src/views/RuleCanvas.vue`（含 useVueFlow 集成）
**提交**：`459451d5`

### 15.3 JSON 路线 + 内部字段 strip（Stage 1.3）

**问题**：原 `JSON.parse(JSON.stringify(...))` 在大图会撞 VueFlow 节点内部的 `parentNode` / `dimensions` / `internals` 等 DOM 引用/循环引用根。

**修复**：新增 `cloneForHistory()` 显式 strip 12 个 VueFlow 内部字段：
```
selected, dragging, parentNode, dimensions, handleBounds, internals, events,
selectable, deletable, focusable, updatable, initialized, resizer, dragHandle
```
**实测**：`structuredClone` 撞 `parentNode` 抛 `DataCloneError`（已验证），回退 JSON 路线更安全。

### 15.4 历史栈瘦身（Stage 1.4 + 衍生）

**修复**：
- `maxHistorySize` 50 → 20 步（覆盖 99% 工作流，内存 -60%）
- `handleSelectionDragStop` 改为内层 `node.selected = ...` 单一变更，不再 `nodes.map(n => ({...n, selected}))` 重建整图

**涉及文件**：`ruleEngine.ts:109-116` + `RuleCanvas.vue:1103-1113`
**提交**：`e08f0677`

### 15.5 updateNodeConfig 内部 mutate（Stage 1.5）

**问题**：原 `node.data = {...}` 整对象引用换掉 → VueFlow diff 整节点 → RuleNode 26 个 el-* 子组件 re-render。

**修复**：
```ts
function updateNodeConfig(nodeId, key, value) {
  const node = nodes.value.find(n => n.id === nodeId)
  if (node?.data) {
    if (!node.data.config) node.data.config = {}
    node.data.config[key] = value
    triggerRef(nodes)  // shallowRef 手动触发
  }
}
```

### 15.6 widget v-memo（Stage 1.6）

**修复**：`RuleNode.vue` 的 `configProperties` v-for 加 `v-memo="[getNodeValue(key)]"`。单 widget 改值时同 schema + 同 value 的兄弟 widget 跳过 vdom diff。

**理论收益**：单字段变更 DOM 更新 O(全部 widget) → O(1)。

### 15.7 缩略图异步化（Stage 2.1）

**问题**：保存时缩略图生成（含 base64 编码 + HTTP POST）阻塞主线程 100-200ms。

**修复**：`handleSave` 用 `requestIdleCallback`（带 `setTimeout(100ms)` 兜底）推迟到浏览器空闲时段。`ElMessage.success` 立即可见，缩略图后台异步上传。

**涉及文件**：`webui/src/views/RuleCanvas.vue:1470-1488`
**提交**：`9446120c`

### 15.8 节点重绘隔离（Stage 2.3）

**修复**：`.node-body` 加 `contain: layout style paint`，隔离单节点 body 内部布局/样式/绘制到自身范围。slider 拖动时不会触发画布其他节点的重排计算。

**涉及文件**：`webui/src/components/rule-engine/RuleNode.vue:762-769`
**提交**：`9446120c`
