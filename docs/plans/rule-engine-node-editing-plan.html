现状：三层断裂的执行链路

当前规则引擎 30 个节点的后端定义、单元测试均已通过（72/72 passed），但从前端画布配置 → 保存 → 加载 → 执行的端到端链路完全断裂。经全链路追踪，发现以下三个核心断裂点：

断裂点 1：节点格式不匹配（list vs dict）

环节格式代码位置
前端保存 nodes_json [{id, type:"rule-node", data:{type, config, ...}}] ruleEngine.ts saveGraph()
parse_graph_data() 返回 {"nodes": [{id, ...}]} graph_manager.py:227
_execute_node() 读取 context.config["nodes"].get(node_id) ← 列表没有 .get() executor.py:555

断裂点 2：节点类型从错误字段读取

# executor.py:559 — 当前代码
node_type = node.get("type")
# ↑ 返回 "rule-node"（VueFlow 节点类型），不是实际执行器类型

# 实际类型在 data.type 中：
node_type = node.get("data", {}).get("type") # → "timer_trigger"

断裂点 3：配置路径不匹配

环节读取路径实际存在路径
前端存储 node.data.config = {interval: 5} ✅ data.config
Executor 读取 node_data.get("params", {}) ❌ 应为 data.config
各节点执行器 self.config.get("params", {}).get("interval") 需包装为 {"params": {interval: 5}}
后果：从数据库加载任何规则图后执行，execute() 会立即崩溃在 executor.py:555（list.get() 不存在）， 或崩溃在 executor.py:559（找不到类型 "rule-node" 的执行器）。 即使越过这两步，所有节点配置值也无法传递到执行器。

Phase 0：修复执行器基础设施（P0）

修复核心执行链路，确保从前端配置到节点执行器的完整数据流畅通。这是所有后续工作的前提。

0.1 统一 nodes 格式：list → dict

backend executor.py execute() / _execute_node()

在 execute() 方法中增加 nodes 格式统一逻辑：

# executor.py ~line 416
nodes = graph_data.get("nodes", {})
# 统一节点格式：列表 → 字典（按 node_id 索引）
if isinstance(nodes, list):
  nodes = {n["id"]: n for n in nodes if "id" in n}

0.2 修正 node_type 读取路径

backend executor.py _execute_node()

VueFlow 节点 node.type === "rule-node"，实际执行器类型在 node.data.type：

# executor.py ~line 559
node_data = node.get("data", {})
node_type = node.get("type")  # ← 得到 "rule-node"
node_type = node_data.get("type") or node.get("type")  # ← 优先读 data.type

0.3 修正 config 读取路径

backend executor.py _execute_node()

前端存储 data.config，各节点执行器需要 self.config = {"params": {...}}：

# executor.py ~line 561
params = node_data.get("params", {})
# 兼容两种格式：前端 data.config（扁平）和测试 data.params（嵌套）
flat_config = node_data.get("config") or node_data.get("params", {})
params = flat_config if isinstance(flat_config, dict) else {}

# 创建执行器时包装为 {params: ...} 格式
executor = registry.create_node(node_type, node_id=node_id, config=node_data)
executor = registry.create_node(node_type, node_id=node_id, config={"params": params})

需要新增的 widget：

2.1 multiselect 多选组件

frontend RuleNode.vue

使用场景：

  • 键盘动作.keys — 从预定义按键列表中选择多个键
  • YOLO触发器.class_names — 选择要检测的类别
  • 目标存在.class_names — 选择要检查的类别

实现方案：

<!-- RuleNode.vue 新增 multiselect 分支 -->
<template v-else-if="schema.widget === 'multiselect'">
  <el-select
    :model-value="getNodeValue(key)"
    multiple
    collapse-tags
    placeholder="请选择..."
    @update:model-value="(v: any) => updateConfig(key, v)"
  >
    <el-option v-for="opt in schema.enum" :key="opt" :value="opt" :label="opt" />
  </el-select>
</template>

获取到的值存储为数组 []，后端各节点 execute() 中已正确处理数组格式。

2.2 toggle 开关组件

frontend RuleNode.vue

使用场景：

  • 计数器.reset_on_trigger — 开关控制是否在触发时重置
  • （未来）定时器.enabled — 开关启用状态

实现方案：

<!-- RuleNode.vue 新增 toggle 分支 -->
<template v-else-if="schema.widget === 'toggle'">
  <el-switch
    :model-value="!!getNodeValue(key)"
    active-text="开启"
    inactive-text="关闭"
    @update:model-value="(v: boolean) => updateConfig(key, v)"
  />
</template>
验证标准：
  • multiselect：键盘动作节点可选择多个按键并正确保存为数组
  • toggle：计数器 reset_on_trigger 开关开/关后保存正确的 boolean 值
  • 所有现有 widget 仍正常工作
