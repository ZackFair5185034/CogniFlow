### 2.1 长期遗留失败已清零

`test_node_executors.py::TestImagePreprocessorNode::test_fallback_when_cv2_missing` 从 2026-06-06 起长期失败。

- **根因**：用例依赖「环境里没装 cv2」这一前提。装了 cv2 的环境里会真的去 `imread` 一个不存在的路径 → 返回 `{"error": ...}` → 断言 `"image" in result` 失败。
- **修法**：改用 `patch.dict('sys.modules', {'cv2': None})` 精确模拟「cv2 不可用」，让用例在任何环境下都测同一条降级分支（`processing_nodes.py` 的 `except ImportError` → 返回原图 + warning）。
- **结果**：后端 0 failed。

## 3. 端到端闭环实测输出

`scripts/e2e/rule_engine_business_flow.py`（隔离 `DATA_DIR`，退出码 0）：

```
执行结果: {"status": "completed", "failed_nodes": [], "error": null,
           "summary": {"node_status": {"n_trigger": "completed", "n_branch": "completed",
                                       "n_wait": "skipped", "n_log": "completed"},
                       "node_count": 4}}
记录状态: completed
节点执行日志条数: 4
  - n_trigger (manual_trigger): completed
  - n_branch (branch): completed
  - n_wait (wait_action): skipped
  - n_log (log_action): completed
业务闭环成立
```

链路：`manual_trigger.triggered (BOOLEAN) → branch.condition (BOOLEAN)`；`branch.true (CONTROL) → log_action.trigger (TRIGGER)`；`branch.false (CONTROL) → wait_action.trigger (TRIGGER)`。

断言要点：
- `branch.condition_result is True` —— 数据真的流到了下游，不是各自空跑；
- `n_log.logged is True` —— 动作层第一次真正可达；
- `n_wait` 为 `skipped` —— 分支选择生效；
- 执行记录 `status=completed`、`node_execution_log ≥ 3` 条、`failed_nodes` 为空。

## 4. 实施中额外发现并修复的真实缺陷

以下问题**不在原计划内**，是实施过程中通过代码走查与测试暴露出来的：

| # | 缺陷 | 影响 | 修复位置 |
|---|------|------|----------|
| 1 | `ExecutionHistory` 无 `error` 列 | 执行错误信息从未落库，历史里看不到失败原因 | 改写 `result_json` 承载错误 |
| 2 | `result_json` 存整份 `node_results` | 可能含 base64 图像，撑大 SQLite | 只落轻量摘要 |
| 3 | `rule_engine.py` 未定义 `logger`、未 import `json` | 路由模块潜在 NameError | 补齐 |
| 4 | 全库**没有任何节点输出 TRIGGER** | 12 个动作/逻辑节点输入悬空，规则图无法成链 | 补 `CONTROL → TRIGGER` 兼容关系 |
| 5 | `CONTROL → TRIGGER` 缺失 | 「分支 → 动作」连不出来 | 端口矩阵补齐（3 条测试锁定） |
| 6 | 节点/边 id 用 `Date.now()` | 同毫秒创建冲突 | 改自增序号 `node_${Date.now()}_${seq}` |
| 7 | `manual_trigger` 输出端口名与前端假设不一致 | 连线校验误判 | 对齐为 `triggered`；核对 `yolo_model` 的真实输出端口 |
| 8 | `nodes` 是 shallowRef，就地改 `data.status` 不触发重算 | 节点状态回填不生效 | 改用独立 `nodeStatusMap`（换引用） |
| 9 | `isDirty` 原为纯 `historyIndex` 比较 | `updateNodeConfig` 不写历史栈 → 改参数不标脏 | 扩展 `_configDirty` 标志位 |
| 10 | VueFlow `addSelectedNodes` 是**替换**选中集语义 | 「已选中 A，再框选含 A 的区域」会把 A 取消 | `syncSelectionToStoreNodes` 改传完整目标集合 |
| 11 | `_indexRebuild` 用 `edges.value.find` 找被删的边 | 被删边已不在数组里 → 句柄索引残留 → 换图后端口显示「已连接」且拒绝重连 | 增 `_indexedEdges` Map 按 id 取回（同时 O(E²)→O(E)） |
| 12 | 草稿序列化含 VueFlow 内部字段 | localStorage 超配额被静默吞掉 → 草稿形同虚设 | 载荷裁剪为业务字段 |
| 13 | 遗留失败用例依赖环境偶然性 | 长期挂着红灯 | 用 `sys.modules['cv2']=None` 精确模拟 |

## 5. 遗留项与未验证项

### 5.1 明确未做（Worker 已上报并经复核确认）

| 项 | 原因 |
|---|------|
| 摄像头设备源采集 | `engine` 的 `VideoReader` 只支持文件路径，`/dev/video0` 类设备源无法接入，保持显式失败 |
| `double_click` / `right_click` 鼠标动作 | 引擎有方法，但既有 `MouseActionConfig` 枚举语义只覆盖 click/move/scroll，其余显式抛错（配置 schema 仍列有这两个值，属遗留不一致） |
| 屏幕采集的异步化 | mss/pyautogui 在 Windows 绑定主线程 GDC 句柄，放工作线程必抛 `'_thread._local' object has no attribute 'srcdc'`，只能同线程同步调用（会短暂阻塞事件循环） |
| `VideoCaptureConfig` 默认值调整 | 本轮已将 `source` 默认从 `"video0"` 改为空串（摄像头设备源不可接入，留默认值会让人误以为配好了） |
| 前端配置编辑器暴露 `region` | 前端无 object widget，暴露会渲染成 `[object Object]` 文本框，故未加入 `get_config_schema()` |

### 5.2 已知行为差异（需产品确认）

1. **框选命中语义收窄**：`store.nodesInRect` 判定的是**节点锚点（position，节点左上角）**是否落在矩形内；
   改造前的 DOM 判定是「节点盒与矩形相交（partial）」。
   → 框选矩形需要盖住节点左上角才算命中，框住节点右下角不算。
   影响面：仅框选边缘节点时。若要恢复 partial 语义，需在调用点按节点尺寸扩展选区（节点尺寸 280×222 CSS px，需按 zoom 换算到画布单位）。

2. **LOD 展开阈值 0.65 → 0.75**：默认视口缩放同步从 0.65 提到 0.75，否则首屏会落在 LOD 0（节点折叠态）。
   后果：中等缩放级别（0.65~0.75）下节点不再展开，节点壳变小、配置区不可见（双击可展开）。

3. **右侧栏常驻占 280px**：工具栏提供收起按钮；未做窄屏自动收起。

### 5.3 未验证

- **人工浏览器走查**：本轮以单元测试 + e2e 脚本 + 构建产物为验收依据，**未做真实浏览器端的交互走查**（属性面板实际渲染、框选手感、图例可读性等）。
- **真实桌面环境下的截屏/键鼠模拟**：单测以打桩验证调用链；真实调用在开发机上做过单次验证（截屏返回 `(3206, 8000, 3)`、带 region `(240, 320, 3)`、视频 `(48, 64, 3)`），未做持续性回归。
- **多用户并发调度**：Task 9 只覆盖单进程内的互斥，未做多进程/多实例竞争验证。
