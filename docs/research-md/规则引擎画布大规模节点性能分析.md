# 规则引擎画布 — 大规模节点性能分析

**日期**: 2026-06-07
**分析范围**: WebUI 前端画布 (VueFlow 1.48 + RuleNode.vue + ruleEngine Store)

---

## 1. 结论概要

| 场景 | 当前上限估值 | 瓶颈 |
|------|-------------|------|
| 静态展示 | 50-80 节点 | DOM 节点数 → 布局卡顿 |
| 拖拽平移 | 30-50 节点 | VueFlow 重渲染 |
| 框选+操作 | 20-30 节点 | Node watcher 重算 |
| 编辑配置 | 无上限 (但反馈延迟) | 字段级 `v-memo` 已优化 |

超过这些阈值后性能会「感觉明显卡顿」。

---

## 2. 关键性能瓶颈

### 2.1 缺少视口虚拟化 (头号瓶颈)

**现状**: `onlyRenderVisibleElements` 未启用 → VueFlow 始终渲染全部节点到 DOM

VueFlow 1.48 内置此功能，当启用后：
- 只渲染当前 viewport 内的节点
- `getNodes` computed 会调用 `getNodesInside()` 作视口裁剪
- 全选时仍需要所有节点（selection 逻辑在 store 内，不受影响）

**估算**: 200 节点画布启用后 → 视口内可见 ~10-20 个 DOM 节点，渲染量减 90%。

**风险**: 自定义节点 (`ruleNode` 类型) 的 Handle 连接线在虚拟化下可能需额外配置。

### 2.2 节点组件渲染开销

每个 `RuleNode.vue` 节点至少包含:

```
节点容器 div (.rule-node)                   1
  标题栏 (.node-header)                    1
  icon + label                              2
  端口区域 (.node-ports)                    1
    每个 input port (Handle + label)       1+ 个
    每个 output port (label + Handle)      1+ 个
  状态指示器 (.node-status)                 1
配置控件 (widget)                          0-6 个
  el-slider / el-input / el-select 等      Element Plus 组件
```

**重型 widget**: `file-picker` 含 `el-input` + 2 个 button + hidden input
**`v-memo`**: 仅字段级 `v-for` 有 `v-memo="[getNodeValue(key)]"`，但节点整体无 `v-memo`

30 节点 × ~20 个元素 ≈ 600 DOM 节点 + Element Plus 组件实例。仅元素数量就接近浏览器的「交互阈值」(推荐 < 500 可交互元素)。

### 2.3 shallowRef + triggerRef 模式

Store 已使用 `shallowRef` + `triggerRef`：
- 好处：深属性变更不会级联 trigger
- 问题：
  - `updateNodeConfig` 每次 mutate 后 `triggerRef(nodes)` → 整个 nodes 数组的 watcher 重算
  - `handleSelectionDragStop` 遍历所有 store.nodes 写 `selected` → O(n)
  - 删除/创建节点用 `filter/map` 生成新数组 → 全量替换消耗 GC

### 2.4 API 加载

当前后端 API `getGraphDetail` 一次性返回整个图的 JSON：
```ts
nodes_json: string  // 所有节点 serialized
edges_json: string  // 所有边 serialized
```

200 节点 × 2KB ≈ 400KB JSON。一次性解析 + `JSON.parse` O(n) + 全量 `map` 到 VueFlow 内部格式。

### 2.5 历史记录栈

```ts
const maxHistorySize = 20
```

每次操作 (create/delete/paste/undo/redo) 都会 `cloneForHistory`：
```ts
cloneForHistory(nodes)  // JSON 深拷贝所有节点
```
20 次 × 200 节点 × 2KB ≈ 8MB 内存占用。GC 频繁会影响流畅度。

## 3. 分场景容量分析

### 3.1 正常编辑场景 (< 30 节点)

**现状流畅度**: ✅ 良好
- rAF 节流的 panning 流畅
- 字段级 `v-memo` 生效
- `shallowRef` 减少无效响应式

**待改进**: 
- 框选 30 节点后 `handleSelectionDragStop` 遍历 ~30 次 — 够快
- 全选 30 节点后拖拽：`setViewport` 有 rAF 节流，但 30 个节点 watcher 仍会重算

### 3.2 中等规模 (30-80 节点)

**现状流畅度**: ⚠️ 部分卡顿
- `handleSelectionDragStop` 遍历 80 次 → ~1-2ms
- VueFlow 内部 `createGraphNodes` diff 80 节点 → ~3-5ms
- 80 个 RuleNode 组件 mount → ~100-200ms 初始渲染

**主要问题**: 打开/加载/保存时全量 JSON 解析 80 × 2KB ≈ 160KB，JS 解析 ~50ms

### 3.3 大规模 (> 80 节点)

**现状流畅度**: ❌ 明显卡顿
- 首次加载 100+ 节点: ~500ms+ 冻结
- 拖拽: 帧率 < 30fps
- 全选 + 删除: 触发多次重新赋值 + GC
- 右键菜单: `handleContextAction` 克隆目标节点 → 大 JSON 反复 stringify

## 4. 优化方向 (优先级排序)

### P0: 启用 `onlyRenderVisibleElements` （预期收益 80%）

```vue
<VueFlow :only-render-visible-elements="true" />
```

这是 VueFlow 自带的视口裁剪。单行改动，收益最大。

**注意事项**:
- 确保 Handle / 连接线在虚拟化下定位正常
- 测试边（edge）在节点被裁剪时的连线是否仍可见
- `vue-flow__transformation` 容器的 `overflow: visible` 可能有干扰

### P1: 节点组件 `v-memo` 包裹 （预期收益 30%）

在 VueFlow 的节点插槽处加不了 `v-memo`（因为节点由 `nodeTypes` 注册渲染），但可在 `RuleNode.vue` 模板根元素加：

```vue
<div
  v-memo="[data.id, data.status, data.config, selected]"
  ...
>
```

这样当 data.config 未变时跳过整节点重渲染。

### P1: `handleSelectionDragStop` 跳过无变化（预期收益 15%）

```ts
function handleSelectionDragStop(...) {
  let changed = false
  for (const n of store.nodes as any[]) {
    if (n.selected !== selectedIds.has(n.id)) changed = true
    n.selected = selectedIds.has(n.id)
  }
  if (changed) triggerRef(store.nodes)
  // 跳过 userSelectionRect 和 triggerRef 如果无变化
}
```

### P2: API 分页/懒加载（预期收益 50%，但整改面大）

后端 `/api/rule-engine/graph/:id` 改为分页返回：
- 首次返回 `{ edges, nodes: nodes.slice(0, 50) }` + `total_count`
- 视口外节点按需加载

### P2: `handlePaste` 批量避免多次 trigger（预期收益 5%）

当前 `handlePaste` 在循环后一次 `store.nodes = [...store.nodes, ...newNodes]`，已是最优。无需额外改。

### P3: 合并历史快照压缩

当前 `cloneForHistory` 已经做了浅拷贝避免污染。如果 20 步历史还是太大，可改为「每 N 步存一次快照」或增量存储，但收益低于其他优化。

## 5. 上限估算矩阵

| 优化 | 50 节点 | 100 节点 | 200 节点 | 500 节点 |
|------|---------|---------|---------|---------|
| 现状 | ⚠️ 微卡 | ❌ 卡顿 | ❌ 不可用 | ❌ 不可用 |
| + `onlyRenderVisibleElements` | ✅ 流畅 | ✅ 流畅 | ⚠️ 边线渲染问题 | ⚠️ 首次加载慢 |
| + `v-memo` 节点层 | ✅ 流畅 | ✅ 流畅 | ⚠️ 轻微 | ❌ 加载慢 |
| + API 分页 | ✅ 流畅 | ✅ 流畅 | ✅ 流畅 | ⚠️ 延迟加载 |
