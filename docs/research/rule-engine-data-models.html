规则引擎数据模型文档

数据库 Schema、JSON 图结构、Pydantic 校验模型

一、概述

本文档定义 CogniFlow 规则引擎的核心数据模型，包括数据库 Schema、JSON 图结构、Pydantic 校验模型。设计参考调研报告的节点数据结构设计和数据库设计章节。

二、数据库 Schema

2.1 规则图表（RuleGraph）

CREATE TABLE rule_graphs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    nodes_json TEXT NOT NULL DEFAULT '{}',
    edges_json TEXT NOT NULL DEFAULT '[]',
    variables_json TEXT NOT NULL DEFAULT '{}',
    is_active BOOLEAN NOT NULL DEFAULT FALSE,
    trigger_type VARCHAR(50) NOT NULL DEFAULT 'manual',
    trigger_config TEXT NOT NULL DEFAULT '{}',
    thumbnail TEXT,
    version INTEGER NOT NULL DEFAULT 1,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
字段类型说明
idINTEGER主键
nameVARCHAR(255)规则图名称
descriptionTEXT规则图描述
nodes_jsonTEXT节点字典（JSON 字符串）
edges_jsonTEXT边列表（JSON 字符串）
variables_jsonTEXT变量字典（JSON 字符串）
is_activeBOOLEAN是否激活（定时执行等）
trigger_typeVARCHAR(50)触发类型：manual / timer / webhook
trigger_configTEXT触发器配置（JSON 字符串）
thumbnailTEXTBase64 缩略图
versionINTEGER版本号
created_atTIMESTAMP创建时间
updated_atTIMESTAMP更新时间

2.2 执行记录表（ExecutionHistory）

CREATE TABLE execution_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    graph_id INTEGER NOT NULL,
    trigger_type VARCHAR(50) NOT NULL DEFAULT 'manual',
    trigger_data TEXT NOT NULL DEFAULT '{}',
    status VARCHAR(50) NOT NULL DEFAULT 'pending',

    completed_at TIMESTAMP,
    total_time_ms INTEGER,
    error_message TEXT,
    result_data TEXT,
    FOREIGN KEY (graph_id) REFERENCES rule_graphs(id)

字段类型说明
idINTEGER主键
graph_idINTEGER关联的规则图 ID

statusVARCHAR(50)状态：pending / running / completed / failed / cancelled
started_atTIMESTAMP开始时间

total_time_msINTEGER总执行耗时（毫秒）
error_messageTEXT错误信息
result_dataTEXT执行结果（JSON 字符串）

四、Pydantic 数据模型

4.1 核心数据类

class PortDefinition(BaseModel):
    """端口定义"""
    name: str
    type: str  # IMAGE, BBOX, TRIGGER, etc.
    required: bool = True
    default: Any = None
    description: str = ""

class NodeDefinition(BaseModel):
    """节点类型定义"""
    type: str
    category: str  # input, detection, processing, action, logic, output
    display_name: str
    description: str
    icon: str
    color: str  # hex color
    inputs: Dict[str, PortDefinition]
    outputs: Dict[str, PortDefinition]

class NodeDefinitionsResponse(BaseModel):
    """节点定义响应"""
    nodes: List[NodeDefinition]
    categories: List[dict]  # {name, display_name, color, icon}

五、节点执行上下文

5.1 ExecutionContext

class ExecutionContext:
    """规则图执行时的上下文，在整个执行期间共享"""

    def __init__(self, execution_id: int, trigger_type: str, trigger_data: Dict[str, Any]):
        self.execution_id = execution_id
        self.trigger_type = trigger_type
        self.trigger_data = trigger_data
        self.node_results: Dict[str, Dict[str, Any]] = {}  # node_id -> output_data
        self.node_status: Dict[str, str] = {}  # node_id -> status
        self.variables: Dict[str, Any] = {}
        self.config: Dict[str, Any] = {}
        self.cancelled = False

    def get_node_result(self, node_id: str, output_name: str) -> Any:
        return self.node_results.get(node_id, {}).get(output_name)

    def set_node_result(self, node_id: str, outputs: Dict[str, Any]):
        self.node_results[node_id] = outputs

    def is_cancelled(self) -> bool:
        return self.cancelled

    def cancel(self):
        self.cancelled = True

六、节点类型定义

6.1 类型兼容性矩阵

# 类型兼容性：源类型 -> 可连接的目标类型
TYPE_COMPATIBILITY = {
    "IMAGE": ["IMAGE", "MASK"],
    "BBOX": ["BBOX"],
    "MASK": ["MASK"],
    "SCORES": ["SCORES"],
    "CLASS_IDS": ["CLASS_IDS"],
    "TRIGGER": ["TRIGGER", "BBOX", "IMAGE", "MASK", "SCORES", "CLASS_IDS", "CONTROL"],
    "CONTROL": ["CONTROL"],
    "MODEL": ["MODEL"],
    "ANY": ["IMAGE", "BBOX", "MASK", "SCORES", "CLASS_IDS", "TRIGGER", "CONTROL", "MODEL", "ANY"],
}

def can_connect(source_type: str, target_type: str) -> bool:
    compatible_types = TYPE_COMPATIBILITY.get(source_type, [])
    return target_type in compatible_types or source_type == "ANY"

7.1 Kahn 算法输入/输出

def build_dependency_graph(nodes, edges):
    """
    从节点和边构建依赖图

    Returns:
        graph: Dict[str, List[str]] - 邻接表，graph[target] = [sources...]
        in_degree: Dict[str, int] - 入度表
    """
    graph = defaultdict(list)
    in_degree = defaultdict(int)
    for node_id in nodes:
        in_degree[node_id] = 0
    for edge in edges:
        graph[edge["target"]].append(edge["source"])
        in_degree[edge["target"]] += 1
    return dict(graph), dict(in_degree)

8.2 节点引用格式对比

ComfyUI（数组索引）：

"inputs": {
  "model": ["checkpoint_loader", 0]
}

CogniFlow（具名引用）：

"inputs": {
  "image": {"node_id": "node_001", "output": "image"}
}

CogniFlow 选择具名引用的原因：

  • 更易读和调试
  • 支持重命名节点后更新引用
  • 便于前端校验连接有效性
