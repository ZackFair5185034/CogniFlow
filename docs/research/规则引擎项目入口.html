一、项目概述

1.1 核心功能目标

CogniFlow 规则引擎是一个可视化编排的视觉感知处理引擎，允许用户通过节点编辑器定义"检测→处理→动作"的完整流程。参考对象是 ComfyUI（最成熟的 AI 节点编辑器）和 Node-RED（工业级流程编排工具）。

目标描述
可视化编排无限画布上通过拖拽、连接节点来构建规则流程
节点类型化输入、检测、处理、动作、逻辑、输出六类节点，类型安全连接
智能执行Kahn 拓扑排序 + 层内并行，支持条件分支
实时反馈WebSocket 推送执行进度，支持中断
持久化规则图保存/加载，支持版本管理

5.1 节点结构（画布节点）

左进右出 — 数据从左向右流动

┌─────────────────────────────────────────────────────────────────┐
│  ■■■ [🔬]  YOLO 检测 v2                        [⋮]            │  ← 顶部3px色条 + 标题
├─────────────┬──────────────────────────────┬───────────────────┤
│             │                              │                   │
│  ● image    │  model:  [yolov8n.pt   ▼]  │  ● image         │
│  ● trigger  │  conf:   [====●====] 0.5   │  ● bboxes         │
│             │  iou:    [====●====] 0.45  │  ● scores         │
│             │  max_d:  [____300____]      │  ● categories     │
│             │  device: [auto       ▼]     │  ● count          │
│             │                              │                   │
└─────────────┴──────────────────────────────┴───────────────────┘
  ← INPUT端口          配置控件区            OUTPUT端口 →

┌─────────────────────────────────────────────────────────────────┐
│ ⚙️ yolov8n.pt | conf: 0.50 | iou: 0.45 | 5 objs                 │  ← 底部摘要
└─────────────────────────────────────────────────────────────────┘
  • 顶部 3px 色条 — 类别标识（绿:input / 青:detection / 黄:processing / 橙:action / 紫:logic / 红:output）
  • 标题栏 — 图标 + 显示名 + 菜单按钮
  • 左侧 — INPUT 端口（接收上游数据）
  • 中间 — 配置控件（slider / dropdown / text / checkbox 等）
  • 右侧 — OUTPUT 端口（流向下游）
  • 底部 — 关键配置摘要（一眼能看到最重要参数）

七、执行状态机

7.1 节点状态

┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐
│  idle   │ ──> │ running │ ──> │ success │ ──> │  idle   │
└─────────┘     └─────────┘     └─────────┘     └─────────┘
     │               │               │
     │               │               │
     v               v               v
┌─────────────────────────────────────────┐
│                  failed                  │
└─────────────────────────────────────────┘
状态说明触发条件
idle空闲/等待执行初始状态 / 执行完成后重置
running执行中节点开始处理
success执行成功节点正常完成
failed执行失败节点处理出错

7.2 图执行流程

  1. 找出所有 INPUT/TRIGGER 节点（无上游依赖）
  2. 并行执行这些节点
  3. 节点完成后，通知依赖它的下游节点
  4. 下游节点检查所有输入是否就绪
  5. (全部就绪) 执行下游节点
  6. 重复直到所有节点完成或遇到错误
  7. 图执行结束，更新执行状态

十、风险识别

风险可能性影响应对措施
Vue Flow 功能限制，无法满足复杂交互中高考虑混用 Canvas 自绘节点（参考 ComfyUI）
节点并行执行导致竞态条件中高使用 asyncio.Lock 保护共享资源
大规模节点（100+）性能下降中中虚拟化渲染 + Web Worker
WebSocket 断连重连高低自动重连 + 消息缓冲
定时任务与服务器重启低中APScheduler + 数据库持久化
